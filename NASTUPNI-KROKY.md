## 1. Залишки — з бази в застосунок, а не через застосунок

**Як зараз.** Адмін залишків вибирає файл звіту 1С на телефоні; застосунок сам розбирає ~100 МБ XML
і пише в Firestore (`stock/{штрихкод}`, пакет частинами, `meta/stock`). Телефони потім читають пакет.
Тобто завантаження в базу йде через застосунок, і залежить від телефона адміна.

**Як треба.** Застосунок лише читає готові дані з бази. Завантаження 1С → база — поза телефоном.

- [ ] Вирішити, хто кладе дані в базу:
  - а) «ЧудоСкан Друк» на ПК (вже є .NET 8): кнопка «Завантажити звіт 1С» або тека, яку програма стежить;
  - б) автоматичне вивантаження 1С за розкладом (обробка 1С пише файл → програма на ПК відправляє);
  - в) хмарна функція: файл у Storage → функція розбирає й пише в Firestore.
- [ ] Перенести розбір звіту (`Xlsx.kt`, `StockPack`) у вибране місце; потоково, без читання 100 МБ у пам'ять.
- [ ] Ключ сервісного акаунта — лише на ПК/в хмарі, ніколи в репозиторії й журналах.
- [ ] У застосунку прибрати завантаження файлу 1С з телефона (лишити тільки перегляд дати й стану).
- [ ] Перевірка: після завантаження на ПК телефон без жодних дій показує нові залишки й дату «Залишки на ДД.ММ».
- [ ] Тести: розбір справжнього звіту (знеособлений зразок), запис у базу (емулятор Firestore), читання в застосунку.

## 3. «Термінал» як POS-термінал

**Є:** кошик, ціна вручну, знижка, передача на касу (QR + код), готівка з рештою, підготовка до оплати
карткою (банк не підключено), спільний кошик з карткою товару.

- [ ] Екран продажу в стилі POS: скан підряд без зайвих дотиків, великі суми, швидкі кнопки кількості.
- [ ] Оплата: готівка, картка (підключити банк / платіжний термінал), змішана оплата.
- [ ] Фіскалізація: ПРРО (наприклад, Checkbox) — чек покупцю, номер фіскального чека в продажу.
- [ ] Повернення й скасування з посиланням на чек.
- [ ] Зміни: відкриття/закриття, X- і Z-звіт, хто працював.
- [ ] Чек: друк на принтері чеків або електронний (SMS / QR).
- [ ] Робота без інтернету: черга продажів, відправка пізніше без дублів.
- [ ] Обмін продажами з 1С (docs/obmin-prodazhiv-1c.md, `sale.schema.json`) — довести до кінця.
- [ ] Ролі: хто може давати знижку, повертати, закривати зміну.
- [ ] Перед стартом — узгодити з бухгалтерією вимоги ПРРО й банк-еквайр.

## 4. Магазини не бачать залишків одне одного

**Зроблено в інтерфейсі.** Співробітник бачить лише свій магазин: вкладки «Свій магазин» і «Змінені»,
без міста й мережі в «Залишках» і в картці товару. Місто й мережа — лише для адміна магазину
й адміна мережі.

**Не зроблено — дані.** Кожен телефон завантажує пакет залишків усієї мережі, а правило
`stock/{штрихкод}` дає читання будь-якому співробітнику. Тобто дані іншого магазину на телефоні є —
їх просто не показано.

- [ ] Пакет на кожен магазин: `stockpacks/{код}/…` лише з кількостями свого магазину.
- [ ] Правила: співробітник читає лише пакет свого магазину (код магазину в профілі), адміни — усе.
- [ ] `stock/{штрихкод}` з кількостями всіх магазинів — читати лише адмінам.
- [ ] Тести правил (`rules-tests`): співробітник ЧО 22 не читає пакет ЧО 11; адмін мережі читає.
- [ ] Вирішити: чи потрібна співробітнику хоч відповідь «є в іншому магазині міста» без кількості.
