# Самовивіз і розрахунок на терміналі

## Замовлення на самовивіз

У застосунку замовлення проходить «Нові» → «Збираю» → «Готові». Продавець обирає активне замовлення. Сканування додає одну одиницю до відповідної позиції в цьому замовленні. Зайвий або сторонній код не змінює підрахунок. Якщо той самий штрихкод є в кількох рядках, скан заповнює перший незавершений рядок. Коли всі позиції зібрано, замовлення переходить у «Готові».

При видачі передплаченого замовлення продавець підтверджує видачу. Для замовлення з оплатою при отриманні спочатку приймає оплату на касі, потім явно підтверджує її та видачу. У поточному режимі дані демонстраційні, а видача прибирає замовлення з активного списку цієї сесії.

### Підключення 1С

Для мапінгу потрібні стабільний ідентифікатор та номер замовлення, магазин видачі, стан і версія запису, ознака оплати, сума в копійках, а також ідентифікатор кожної позиції, штрихкод або артикул та кількість. Для перевірки досить знеособленого вивантаження одного замовлення з кількома позиціями.

Під час підключення приймач звіряє магазин із довідником та повторно завантажує той самий запис без дублювання. Дані видаються лише для магазину авторизованого працівника. Прогрес збирання прив'язується до ідентифікатора позиції. Його оновлення перевіряє версію замовлення, щоб зміна з 1С або іншого пристрою не затерла новий стан. Видача має фіксуватися в історії з часом і працівником. Які статуси повертаються в 1С, визначається під час підключення джерела.

## Термінал

Кошик формує суму в гривнях із цінами в цілих копійках. Екран «Сума для термінала» доступний після визначення ціни всіх позицій. Він показує суму продавцю для введення на терміналі магазину.

### Підключення термінала та ПРРО

1. Зафіксувати склад кошика, суму, валюту й унікальний номер спроби оплати перед викликом термінала.
2. Після відправлення показати очікування. У разі тайм-ауту з'ясувати стан цієї ж спроби через термінал. Повторний запит із тим самим номером не повинен ініціювати ще одне списання.
3. Підтвердити успіх за відповіддю термінала із відповідним номером спроби, сумою та валютою. Відмову та скасування зберігати окремо. Невідомий стан потребує звірки перед повторною оплатою.
4. Зберігати результат оплати та ідентифікатор фіскального чека окремо. Ідентифікатори операції й чека потрібні для повторної перевірки без повторного списання.

Поля й команди встановлюються після отримання специфікації конкретного термінала та тестового контуру. Документ описує поведінку ЧудоСкан і очікуваний обмін даними.

## Що залишилося до промислового запуску

- **Замовлення з 1С.** Узгодити спосіб обміну й отримати зразок. Підключити джерело, зберігати хід збирання й історію видачі між сеансами, перевірити оновлення з двох пристроїв.
- **Приймання та переміщення.** Звірити номери й рядки накладної з документом 1С. Узгодити зі складом, які поля, коди магазинів і статуси потрібні для імпорту CSV або обміну через API. Перевірити часткове приймання, повторну відправку й відкликання документа.
- **Інвентаризація.** Зараз звірка відбувається на рівні магазину. Для звірки по стелажах потрібні відповідні залишки або карта зберігання. Узгодити, хто затверджує розбіжності перед проведенням у 1С.
- **Термінал і ПРРО.** Визначити модель термінала й отримати специфікацію тестового контуру. На тесті перевірити успіх, відмову, скасування, тайм-аут, повторне звірення та фіскальний чек.
- **Перевірка перед випуском.** Пройти сценарії з працівниками різних ролей, камерою фізичного пристрою Android, тестовим звітом 1С і налаштованим тестовим терміналом. Для веб-адмінки перевірити таблиці та імпорт після складання GitHub Pages.
