# Як вносити зміни

## Правила

- **Інтерфейс — лише українською.** Тексти в коді, комітах і документації — теж українською.
- **Жодних ключів** сервісних акаунтів, банку, ПРРО, паролів і токенів у репозиторії, програмах і журналах.
- **Жодних персональних даних**: email і телефони людей, реальні залишки чи ціни — лише знеособлені приклади. Реальні файли 1С не комітити.
- **Кожна зміна — з тестами.** Великі файли (xlsx 1С ~100 МБ) читати потоково.
- **Ліміти Firestore** (безкоштовно на добу: 50 000 читань, 20 000 записів, 20 000 видалень) — кожне рішення має в них вкладатися; у PR вказуйте, скільки додає зміна.

## Гілки й коміти

- `main` — те, що в релізі. Працюємо в гілках: `<коротка-назва>` (`terminal`, `onovlennia`), одна задача — одна гілка й один PR.
- Коміт — одна завершена думка, заголовок до ~70 символів, у тілі — що і навіщо:
  `Залишки: фонове завантаження пакета, дата, видалення старих stock/…`
- CI запускається на PR і на `main`: без зеленого CI не зливаємо.

## Тести перед PR

```bash
./gradlew :app:lintDebug :app:testDebugUnitTest :app:testReleaseUnitTest   # Android
cd rules-tests && npm test                                                  # правила Firestore
dotnet test printer/ChudoScan.Print.Tests                                   # ЧудоСкан Друк
cd core && cargo test && cargo clippy --all-targets -- -D warnings          # Rust-ядро
```

Шлях до проєкту — латиницею (Android Gradle Plugin не збирає з кирилицею в шляху).
Змінили екран — оновіть знімки: `./gradlew :app:recordPaparazziDebug` (і `docs/img`, якщо екран є в документації).
Змінили mermaid — перевірте, що діаграма відкривається на GitHub.

## Правила Firestore

- Нова колекція чи поле — білий список полів, перевірка типів, тести «можна» і «не можна» в `rules-tests/rules.test.js`.
- Після злиття: `firebase deploy --only firestore:rules`.

## Як випустити версію

**Застосунок:**
1. Оновіть [CHANGELOG.md](CHANGELOG.md).
2. `git tag -a vX.Y -m "Що нового"` (слово «обов'язкове» в тексті — обов'язкове оновлення) → `git push origin vX.Y`.
3. CI збирає APK з release-ключем і публікує `ChudoSkan-X.Y.apk`, `ChudoSkan.apk`, `version.json`.
4. Завантажте APK на Google Диск і опублікуйте в застосунку — [docs/onovlennia.md](docs/onovlennia.md).

**ЧудоСкан Друк:** `git tag -a printer-vX.Y.Z -m "…"` → `git push origin printer-vX.Y.Z` → інсталятори в релізі й автооновлення через `printer-latest`.
